## 이관 규칙

1. 최종 상태의 근거와 QA·Git·배포 기록을 확인한다.
2. ACTIVE의 Issue 전체를 ID·수행 기록·상태 이력과 함께 이 파일로 이동한다. 검증·인계 증거를 보존한다.
3. Domain TASKS, 관련 문서·Issue·QA 보고서의 링크를 이 파일의 동일 ID 앵커로 변경한다.
4. ACTIVE 원본을 제거해 상태 원본을 하나로 유지한다.
5. 종료 후 새 결함은 새 Issue로 생성하고 이전 기록을 참조한다. 과거 검증 결과를 덮어쓰지 않는다.
